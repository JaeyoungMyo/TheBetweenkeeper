# U4 상점 비즈니스 로직 모델 (Business Logic Model)

**unit**: U4 상점 (Shop)
**기준**: `construction/plans/u4-shop-functional-design-plan.md` (FD-U4-1 ~ 11 답변 반영), 기획서 9.1 ~ 9.5

던전 1개를 완료하면 상점이 열립니다. 상점에서 판매 요청 아이템을 출력공간으로 옮겨 판매하고, 구매품을 받습니다.

---

## 1. 상점 흐름 (ShopFlow)

```
[던전 완료 → 수면 30초 (U3)]
   │ SHOP_HANDOFF 신호
   ▼
[상점 열림 OPEN]
   │ ① 판매 요청 목록 생성 (창고 아이템 중 무작위, 던전 1 = 2개)
   ▼
[판매 SELL] ── 출력공간에 올린 요청 아이템을 판매 확정 → 골드 지급, 아이템 sold
   │ ② 요청 외 아이템 → 맵 어딘가로 자동 이동 (FD-U4-5 X)
   ▼
[구매 BUY] ── 구매 품목 추첨 (가중치, 던전 1 = 4개)
   │ ③ 품목마다 골드 차감 (부족하면 건너뜀), 구매품 생성
   │ ④ 구매품은 맵에 무작위로 떨어짐 (incoming)
   ▼
[상점 닫힘 CLOSED] → 다음 던전 준비 (U3 시작)
```

- 상점은 던전 완료마다 정확히 한 번 열립니다 (BR-U4-01).
- 상점 안에서 판매와 구매의 순서는 "판매 → 구매" 입니다. 판매로 번 골드를 구매에 쓸 수 있습니다 (BR-U4-02).

## 2. 판매 (SellFlow)

- 판매 요청 목록은 상점이 열릴 때 정합니다. 후보는 선반 · 바닥 · 들고 있는 아이템입니다. 던전 1 은 2개입니다 (BR-U4-03).
- 판매 요청 아이템을 출력공간에 옮기면 판매할 수 있습니다. 출력공간은 용량 제한이 없고, 아이템을 하나씩 넣습니다 (FD-U4-2 A).
- 판매 확정 시, 요청 아이템만 판매합니다 (BR-U4-04). 판매가는 U2 규칙 (무게 × 10, 판매가 보너스 증강 적용) 을 씁니다. 나중에 아이템별 판매가 (`base_price`) 로 바꿀 예정입니다 (BR-U4-05).
- 출력공간에 요청되지 않은 아이템이 있으면 판매하지 않고, 맵 어딘가로 자동 이동합니다 (BR-U4-06).
- 판매되면 아이템은 `sold` 가 되고 창고에서 사라집니다.

## 3. 구매 (BuyFlow)

- 구매 품목은 가중치 추첨으로 정합니다. 방문마다 정해진 개수를 뽑습니다. 던전 1 은 4개입니다. 같은 품목이 여러 번 나올 수 있습니다 (BR-U4-07, FR-18).
- 품목마다 골드를 차감합니다. 골드가 부족하면 그 품목만 건너뜁니다. 골드 부족 메시지를 띄우고 아이템은 생기지 않습니다 (BR-U4-08, US-21).
- 구매품은 `incoming` 상태로 맵에 무작위 위치에 떨어집니다. 입력공간은 없습니다 (FD-U4-1 C, FD-U4-8 X, BR-U4-09).
- 구매품 수량만큼 아이템 인스턴스를 만듭니다 (BR-U4-10).
- 구매품은 다음 던전의 신규 아이템입니다 (D-18). 던전의 무작위 입고 (U3) 와는 별도 경로로 함께 들어갑니다 (FD-U4-9 B, BR-U4-11).

## 4. 열린 항목 (향후 작업)
1. 아이템별 판매가 (`base_price`) 로 바꾸기 (FD-U4-4 향후 B)
2. 던전 스타일과 난이도별 드롭 테이블 (FD-U4-9 향후)
3. 대량 상자는 이번 범위에서 만들지 않음 (FD-U4-10 A, 상자 개념 없음)
