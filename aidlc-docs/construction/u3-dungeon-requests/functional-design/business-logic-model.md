# U3 던전 · 요청 비즈니스 로직 모델 (Business Logic Model)

**unit**: U3 던전 · 요청 (Dungeon & Requests)
**기준**: `construction/plans/u3-dungeon-requests-functional-design-plan.md` (FD-U3-1 ~ 14, 전부 추천안 A 채택), `business-rules.md`, `domain-entities.md`

U3 는 던전 1개의 진행 (전투 → 완료 → 수면 → 상점 호출 직전) 과 긴급 요청을 소유합니다. 상점 자체, 저장 파일 형식은 제외합니다 (U4, U5).

---

## 1. 던전 흐름 상태 머신 (DungeonFlow)

```
[대기 READY]
   │ 던전 시작 (정리 대상 = 미정리 incoming 누적 포함)
   ▼
[전투 IN_BATTLE] ──전투 종료──▶ 남은 전투 있음? ──예──▶ [전투 IN_BATTLE]
   │                              │아니오
   │                              ▼
   │                    [던전 완료 DUNGEON_COMPLETE]  ← 정리 상태 검사 안 함
   │                              │ 진행 중 요청이 있으면 실패 처리 (BR-U3-13)
   │                              ▼
   │                    [수면 SLEEP, 30초]  ← 전투 · 요청 발생 없음 (BR-U3-12)
   │                              │ 30초 경과
   │                              ▼
   │                    [상점 호출 SHOP_HANDOFF]  → U4 로 넘김 (상점 내부는 U4)
   │
   └──요청 실패 누적 3회 도달 (어느 상태에서든 판정)──▶ [게임오버 GAME_OVER]
```

- 전투 횟수 `N` 은 던전 시작 시 3~5 중 무작위로 정하고 던전 안에서 바뀌지 않습니다 (BR-U3-01).
- 던전 완료 판정은 `남은 전투 수 = 0` 만 검사합니다. 아이템 상태는 보지 않습니다 (FR-13, D-15).

## 2. 전투 입고 흐름

- 전투 `k` 가 끝나면 해당 전투의 신규 아이템을 `incoming` 으로 입고합니다 (AC-11-2).
- 던전당 신규 아이템 총량 `T` 를 전투 수 `N` 으로 나눕니다. 몫을 각 전투에 주고, 나머지는 마지막 전투에 더합니다 (BR-U3-03).
  - 예: 던전 1, `T = 10`, `N = 3` → 3, 3, 4
- 미정리 `incoming` 아이템은 던전 완료 뒤에도 상태가 바뀌지 않고, 다음 던전 시작 시 정리 대상에 그대로 남습니다 (AC-14-1, FR-15).

## 3. 긴급 요청 흐름 (RequestController)

```
[후보 없음] ── 창고에 요청 가능한 incoming/stored 아이템 없음 → 요청을 만들지 않음 (BR-U3-08)
   
[발생 대기 PENDING] ──던전의 요청 발생 시점 도달 (전투 중 무작위)──▶ [진행 ACTIVE]
[진행 ACTIVE] ──요청 대상 아이템을 모두 전달 공간으로 옮김 (제한 시간 내)──▶ [성공 SUCCESS]  → 보상 지급, 전달된 아이템 삭제
[진행 ACTIVE] ──제한 시간 경과──▶ [실패 FAILED]  → 실패 누적 +1
[진행 ACTIVE] ──던전 완료 시점에 아직 진행 중──▶ [실패 FAILED] → 실패 누적 +1 (BR-U3-13)
```

- 던전당 요청 수 `R` 은 던전 데이터로 정합니다. 던전 1 은 `R = 1` (기획서 8.2).
- 요청은 한 번에 1건만 `ACTIVE` 입니다. 다음 요청은 현재 요청이 끝난 뒤 발생 시점이 되어야 생성합니다 (BR-U3-07).
- 발생 시점은 전투 진행 중 무작위입니다. 수면 중에는 발생하지 않습니다 (BR-U3-12).
- 요청 수량 Q 는 2~10 개입니다. 던전 난이도가 올라갈수록 늘어나며, 던전 데이터로 정합니다 (BR-U3-17).
- 요청 대상 Q 개를 창고에서 고릅니다. 제한 시간은 30초 설정값입니다 (BR-U3-06).

### 3-1. 요청 대상 예약 · 전달
- 요청이 `ACTIVE` 가 되면 대상 아이템을 `reserved` 로 바꿉니다. 판매를 거부합니다 (FR-23, AC-17-1).
- 요청이 `FAILED` 로 끝나면 `reserved` 를 풀고 아이템은 요청 전 상태로 돌아갑니다 (BR-U3-10).
- 요청이 `SUCCESS` 로 끝나면 전달 공간으로 옮긴 아이템은 게임에서 삭제합니다 (BR-U3-18).

## 4. 실패 누적과 게임오버

- 실패 누적 값 `F` 는 요청 종류와 무관하게 하나의 값으로 셉니다 (AC-16-3, D-06).
- `FAILED` 가 확정될 때마다 `F += 1` 입니다 (BR-U3-09).
- `F = 3` 이 되면 즉시 `GAME_OVER` 로 전환하고 게임오버 화면에 `F` 를 표시합니다 (AC-16-2).
- 게임오버 후에는 처음부터 새 게임을 시작합니다. 모든 진행 값을 초기화합니다 (BR-U3-11).

## 3-2. 전달 판정

- 성공 조건: 요청 대상 Q 개를 **모두** 특정 전달 공간으로 옮긴 순간 (제한 시간 내) 입니다.
- 일부만 옮긴 상태에서 제한 시간이 끝나면 실패입니다. 이미 옮긴 아이템은 삭제하지 않고, 실패 후 `reserved` 해제와 함께 원래 상태로 돌아갑니다 (BR-U3-19).

## 5. 보상

- 요청 성공 시 요청 데이터에 정해진 골드와 EXP 를 지급합니다. 특별 보상 종류는 U3 에서 두지 않습니다 (BR-U3-05).
- 실패와 취소에는 보상이 없습니다.

## 6. 열린 항목 (검토 시 확인)
1. 던전별 요청 수량 Q 의 값 (던전 1 = 2 를 초기값으로 둠, 2~10 범위 안에서 난이도 따라 증가).
2. 제한 시간 30초는 초기 설정값이며 밸런스 조정 대상입니다.
3. 전달 공간의 위치와 형태는 U3 Code Generation · 화면 설계에서 정합니다 (구매품 공간 P-02 와 연결 여부 확인 필요).
