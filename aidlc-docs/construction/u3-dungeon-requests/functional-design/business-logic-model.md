# U3 던전 · 요청 비즈니스 로직 모델 (Business Logic Model)

**unit**: U3 던전 · 요청 (Dungeon & Requests)
**기준**: `construction/plans/u3-dungeon-requests-functional-design-plan.md` (FD-U3-1 ~ 14 추천 A 채택, 정정 1·2·3 반영), `business-rules.md`, `domain-entities.md`

U3 는 던전 1개의 진행 (전투 → 완료 → 수면 → 상점 호출 직전) 과 긴급 요청 (퀘스트) 을 소유합니다. 상점 내부와 저장 형식은 제외합니다 (U4, U5).

---

## 1. 던전 흐름 상태 머신 (DungeonFlow)

```
[대기 READY]
   │ 던전 시작 (미정리 incoming 누적 포함)
   ▼
[전투 IN_BATTLE] ──전투 종료──▶ 남은 전투 있음? ──예──▶ [전투 IN_BATTLE]
   │                              │아니오
   │                              ▼
   │                    [던전 완료 DUNGEON_COMPLETE]  ← 정리 상태 검사 안 함
   │                              │ 진행 중 퀘스트가 있으면 실패 처리 (BR-U3-13)
   │                              ▼
   │                    [수면 SLEEP, 30초]  ← 전투 · 퀘스트 발생 없음 (BR-U3-12)
   │                              │ 30초 경과
   │                              ▼
   │                    [상점 호출 SHOP_HANDOFF]  → U4 로 넘김
   │
   └──퀘스트 실패 누적 3회 도달 (어느 상태에서든 판정)──▶ [게임오버 GAME_OVER]
```

- 전투 횟수 N 은 던전 시작 시 3~5 중 무작위로 정하고 던전 중 바뀌지 않습니다 (BR-U3-01).
- 던전 완료 판정은 남은 전투 수만 봅니다. 아이템 상태는 보지 않습니다 (FR-13, D-15).

## 2. 전투 입고 흐름
- 전투 k 가 끝나면 그 전투의 신규 아이템을 `incoming` 으로 입고합니다 (AC-11-2).
- 던전 신규 아이템 총량 T 를 N 으로 나눠 균등 입고하고, 나머지는 마지막 전투에 더합니다 (BR-U3-03). 예: 던전 1, T = 10, N = 3 → 3, 3, 4.
- 미정리 `incoming` 아이템은 던전이 끝나도 상태가 바뀌지 않고 다음 던전의 정리 대상에 남습니다 (FR-15).

## 3. 퀘스트 (긴급 요청) 구조

퀘스트 1건은 **줄 (Line) 여러 개**로 구성됩니다. 줄 하나는 `아이템 종류 × 필요 개수` 입니다.

```
[회복약 (0/3)]    ← 줄 1 (종류, 필요 3)
[해독제 (0/1)]    ← 줄 2 (종류, 필요 1)
```

- 퀘스트의 총 수량 Q (모든 줄 필요 개수의 합) 는 2~10 입니다. 던전 난이도가 올라갈수록 늘어납니다 (BR-U3-17).
- 줄 수 (종류 수) 는 1~3 입니다. 던전 데이터로 정합니다 (BR-U3-18).
- 제한 시간은 30초 설정값입니다 (BR-U3-06).

### 3-1. 퀘스트 생성 (발생)
- 던전마다 퀘스트 수 R 은 데이터로 정합니다. 던전 1 은 R = 1 입니다 (기획서 8.2). 한 번에 1건만 진행합니다 (BR-U3-07).
- 발생 시점은 전투 진행 중 무작위입니다. 수면 중에는 발생하지 않습니다 (BR-U3-14, BR-U3-12).
- 줄은 창고에 해당 종류 아이템이 1개 이상 있는 종류 중에서 고릅니다. 줄 필요 개수는 Q 를 줄 수로 나눠 정하며, 나머지는 앞 줄에 더합니다. 창고에 쓸 수 있는 종류가 없으면 퀘스트를 만들지 않습니다 (BR-U3-08).

### 3-2. 전달 공간과 줄 체크 (진행)
- 플레이어가 전달 공간에 아이템을 올리면, 그 아이템과 종류가 같은 줄의 전달 수가 1 올라갑니다. 예: 회복약 (0/3) → 회복약 1개 올림 → (1/3). 줄의 필요 개수 이상은 세지 않습니다 (BR-U3-09).
- 줄의 전달 수가 필요 개수에 도달하면 그 줄은 **완료** 로 표시합니다 (BR-U3-10).
- 줄과 종류가 맞지 않는 아이템은 전달 공간에 그대로 머무르고 퀘스트에 세지 않습니다 (BR-U3-11).
- 전달 공간에 올린 아이템은 이 단계에서 삭제하지 않습니다.

### 3-3. 성공 · 실패 판정
- **성공**: 모든 줄이 완료되었을 때 (제한 시간 내). 성공 순간 각 줄의 필요 개수만큼만 전달 공간에서 삭제합니다. 초과분은 남깁니다 (BR-U3-12).
  - 예: 회복약 4개 올림, 필요 3 → 3개 삭제, 1개 남음.
- **실패**: 제한 시간이 끝날 때까지 모든 줄이 완료되지 않은 경우. 전달 공간의 아이템은 전부 그대로 남습니다. 삭제하지 않습니다 (BR-U3-13).
- 실패 시 창고로 돌아가지 않습니다. 전달 공간에 남은 아이템은 다음 퀘스트에서 다시 셉니다 (BR-U3-15).

### 3-4. 예약
- 퀘스트 생성 때 창고의 아이템을 예약하지 않습니다. 전달 공간에 올라간 아이템은 판매할 수 없습니다 (BR-U3-23).

## 4. 실패 누적과 게임오버
- 실패 누적 값 F 는 퀘스트 종류와 무관하게 하나의 값으로 셉니다 (AC-16-3, D-06).
- 퀘스트가 실패로 확정되면 F += 1 입니다 (BR-U3-16).
- F = 3 이 되면 즉시 GAME_OVER 로 전환하고 게임오버 화면에 F 를 표시합니다 (AC-16-2).
- 새 게임은 모든 진행 값을 초기화합니다 (BR-U3-17).

## 5. 보상
- 성공 시 퀘스트 데이터에 정한 골드와 EXP 를 지급합니다. 특별 보상 종류는 U3 에서 두지 않습니다 (BR-U3-05).
- 실패에는 보상이 없습니다.

## 6. 검토가 필요한 가정 (사용자 확인 요청)
1. **삭제 시점**: 이 설계는 아이템을 **퀘스트 성공 순간** 에 삭제합니다. 전달 공간에 올리는 즉시 삭제하는 방식이 아닙니다. 실패하면 모두 남습니다.
2. **남은 아이템 재사용**: 실패나 초과분으로 전달 공간에 남은 아이템은 다음 퀘스트에서 다시 셉니다.
3. **던전 1 값 (초기값, 밸런스 조정 대상)**: Q = 2 (줄 수 1 ~ 2), 제한 시간 30초. 예시 퀘스트의 Q = 4 는 던전 2 이후 값입니다.
