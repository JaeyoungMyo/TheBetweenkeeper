# 요구사항 문서 (Requirements)

**기준 문서**: `아공간_관리인_최종_게임_기획서_Godot_개발명세서_v1.0.md` (기획서 원문은 아래 "변경 반영" 절에 기록한 부분만 바꿨습니다)
**확인 기록**: `requirement-verification-questions.md` (Q1~Q15), `requirement-clarification-questions.md` (C1~C5), `requirement-clarification-round2-questions.md` (F1~F3)

## 의도 분석 (Intent Analysis)

- **사용자 요청**: 2D 탑뷰 정리 시뮬레이션 · 로그라이크 성장 게임을 Godot 4.7.2로 제작하고, HTML5 빌드로 itch.io에 배포
- **요청 유형**: New Project
- **범위 추정**: System-wide (정리, 요청, 경제, 던전 진행, 상점, 저장, 배포 전체)
- **복잡도 추정**: Complex
- **요청 명확성**: 기획서는 상세하나, 충돌 · 미정 항목 8건을 질문으로 확정함
- **깊이**: Comprehensive (추적성을 갖춘 기능 · 비기능 요구사항)

## 기능 요구사항 (Functional Requirements)

| ID | 요구사항 | 기준 (검증 방법) | 근거 |
| --- | --- | --- | --- |
| FR-01 | 플레이어는 WASD 또는 방향키로 2D 탑뷰 맵에서 이동한다. 벽과 시설에 충돌한다 | 벽을 통과하지 않음 (테스트 체크리스트) | 기획서 3.1 |
| FR-02 | 아이템 목록을 화면 한쪽에 항상 표시한다 | 게임 실행 중 목록이 가려지지 않음 | D-14 |
| FR-03 | 선반을 클릭하면 선반 패널이 열린다. 패널에서 목록의 아이템을 드래그해 선반에 적재한다. X 버튼 또는 다시 클릭으로 닫는다 | 패널 열림 상태에서만 적재 가능, 닫으면 패널 숨김 | D-14, C1 |
| FR-04 | 패널이 닫힌 상태에서 아이템을 맵 아무 곳에나 드롭하면 현재 위치에 버려진다 | 드롭 위치에 아이템이 놓이고 목록에서 빠짐 | D-14 |
| FR-05 | 바닥 아이템은 마우스를 올리면 이름이 표시되고, 클릭하면 주운다. 키보드 상호작용 키로도 줍는다 | 두 방식 모두 줍기 동작 성공 | D-16, F3 |
| FR-06 | 각 시설은 최대 적재 무게를 가진다. 현재 적재 무게와 배치 아이템 무게의 합이 최대를 넘으면 적재를 거부한다 | 한도 초과 시 적재 불가 (테스트 체크리스트) | 기획서 3.4, 10 (무게 기반으로 변경) |
| FR-07 | 무게 초과로 거부되면 "무게 초과" 메시지를 표시하고, 아이템은 그 자리 바닥에 떨어진다 | 메시지 표시, 아이템 위치가 바닥으로 변경 | D-09 |
| FR-08 | 아이템은 무게를 가진다. 무게가 클수록 들고 이동할 때 이동 속도 감소가 커진다 | 무게 증가에 따라 속도 감소량 단조 증가 | 기획서 3.3 (무게 기반) |
| FR-09 | 아이템 인스턴스는 `incoming`, `carried`, `stored`, `requested`, `sold`, `reserved` 상태를 가진다 | 상태 전환이 정의된 규칙만 따름 | 기획서 4.3 |
| FR-10 | 수납 시 EXP를 지급한다. 같은 아이템 인스턴스로 EXP를 중복 획득할 수 없다 | `is_exp_claimed`로 1회 제한 | 기획서 5.1 |
| FR-11 | 레벨업 시 증강 후보 중 하나를 선택한다. 후보는 중복 제한을 둔다 | 같은 증강이 연속 제시되지 않음 (수치 기준은 테스트에서 확정) | 기획서 5.2 |
| FR-12 | 던전은 전투 3~5회로 구성된다. 전투마다 아이템이 입고된다 | 던전당 전투 횟수가 설정 범위 안 | D-04 |
| FR-13 | 던전 완료는 전투가 모두 끝나면 판정한다. 아이템 정리 여부는 완료 조건이 아니다 | 미정리 상태에서도 던전 완료 처리됨 | D-15, F2 |
| FR-14 | 던전 종료 후 30초 수면 이벤트를 발생시킨다. 시간은 설정값이다 | 이벤트 지속 시간이 설정값과 일치 | D-15, C4 |
| FR-15 | 미정리 아이템은 `incoming` 상태로 남아 다음 던전의 정리 대상에 누적된다 | 다음 던전 시작 시 미정리 아이템이 목록에 남아 있음 | D-15 |
| FR-16 | 던전 종료 후 용사가 상점을 방문하는 연출을 실행한다. 일반 낱개 구매품이 입고된다 | 던전마다 방문 연출 발생 | D-15, Q4 해석 (기획서 9와 함께 확인 필요, 가정 A-01) |
| FR-17 | 던전 3개를 완료할 때마다 대량 상자 입고 상점 이벤트를 추가로 발생시킨다 | 3던전마다 정확히 한 번 발생 | 기획서 9.1 |
| FR-18 | 상점 구매 품목은 가중치 기반 무작위로 결정한다. POC 범위에서 던전 특성 규칙과 무기 · 방어구 구매는 제외한다 | POC 빌드에서 가중치 방식만 동작 | D-05, C3 |
| FR-19 | 상점 구매 비용은 공유 골드에서 차감한다. 골드가 부족하면 구매가 실패한다 | 잔액 부족 시 구매 실패 | 기획서 6.1, 9.2 |
| FR-20 | 용사는 긴급 요청을 전투 중에도 할 수 있다. 요청에는 제한 시간이 있다 | 제한 시간 내 전달 시 성공, 초과 시 실패 | 기획서 7.1~7.2, Q4 |
| FR-21 | 긴급 요청 실패는 누적한다. 누적 3회에 도달하면 게임오버 처리한다 (요청 종류 무관) | 3회 실패 시 게임오버 화면 전환 | D-06, F1 |
| FR-22 | 긴급 요청 성공 시 골드, 추가 EXP 또는 특별 보상을 지급한다 | 보상 지급 확인 | 기획서 7.3 |
| FR-23 | 판매 시 판매가만큼 골드를 얻고, 아이템은 `sold` 상태가 된다. `reserved` 및 요청 중 아이템은 판매할 수 없다 | 예약 아이템 판매 시도 시 거부 | 기획서 6.3 |
| FR-24 | 시설은 골드로 구매하고 확장할 수 있다. 확장은 최대 적재 무게를 늘린다 | 구매 후 최대 무게 증가 | 기획서 10.2 |
| FR-25 | 던전 완료 시 자동 저장한다. 저장에는 아이템 위치 · 상태, 골드, 시설, 플레이어 성장, 던전 진행, 요청 실패 횟수를 포함한다 | 저장 후 재실행 시 동일 상태 복원 | D-12, 기획서 14.8 |
| FR-26 | 웹 빌드는 브라우저 저장과 함께 세이브 파일 내보내기/불러오기를 지원한다 | 내보낸 파일을 다른 브라우저에서 불러올 수 있음 | D-03 |
| FR-27 | 화면 해상도는 1280x720 (16:9) 고정이며, 창 크기 조절 시 비율을 유지한다 | 창 크기 변경 시 레터박스 등으로 비율 유지 | D-10 |
| FR-28 | UI 텍스트는 한국어를 기본으로 한다. 영어 번역은 MVP 이후 추가한다 | 한국어 리소스로 모든 UI 표시 | D-11 |
| FR-29 | 튜토리얼 단계에서는 아이템 10개를 사용한다. 이후 던전 1부터 기획서 8.2 기준으로 진행한다 | 튜토리얼 아이템 수 10 | D-07 |

## 비기능 요구사항 (Non-Functional Requirements)

| ID | 요구사항 | 측정 기준 | 비고 |
| --- | --- | --- | --- |
| NFR-01 | 데스크톱 빌드는 목표 프레임레이트를 유지한다 | 아이템 200개, 창고 1개 기준 60 FPS 이상 (기준 PC 사양은 테스트에서 확정) | 가정 A-02 |

| NFR-03 | 저장 데이터는 아이템 복제 · 누락 없이 복원된다 | 저장 · 복원 10회 반복 후 아이템 수와 상태가 동일 | 기획서 17 |
| NFR-04 | 골드 잔액 변경은 `GoldManager` 한 곳을 통해서만 한다 | 코드 검사에서 다른 경로의 직접 대입 0건 | 기획서 13.4 |
| NFR-05 | 아이템 종류 데이터와 아이템 인스턴스 데이터는 분리한다 | `ItemData`와 `ItemInstance` 분리 구조 확인 | 기획서 13.6 |
| NFR-06 | 빌드 산출물은 itch.io에 zip으로 업로드 가능한 구조로 만든다 (index.html 포함) | 업로드 후 "Play in browser" 실행 확인 | 기획서 Phase 11 |
| NFR-07 | 웹 빌드는 스레드를 사용하지 않는다 (추가 서버 헤더 불필요) | Export 설정 확인 | 기획서 Phase 11 |
| NFR-08 | 웹과 데스크톱 모두 Compatibility 렌더러를 사용한다 | 프로젝트 설정 확인 | D-02 |
| NFR-09 | 확장 PBT 규칙을 전면 적용한다. 순수 로직 (무게 계산, 증강 중복 제한, 골드 계산, 저장 왕복) 에 속성 기반 테스트를 작성한다 | 대상 모듈별 PBT 테스트 존재 | Q15 A |
