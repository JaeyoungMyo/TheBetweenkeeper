# Unit 의존성 매트릭스 (Unit of Work Dependency)

행 (의존하는 unit) → 열 (의존받는 unit). `O` = 직접 의존 (메서드 호출 또는 데이터), `S` = 시그널 구독, `-` = 없음.

| 의존 \ 대상 | U1 창고 · 조작 | U2 성장 · 경제 | U3 던전 · 요청 | U4 상점 | U5 저장 · 플랫폼 |
| --- | --- | --- | --- | --- | --- |
| **U1 창고 · 조작** | - | - | - | - | - |
| **U2 성장 · 경제** | O (아이템 EXP 지급 대상, 판매 가격용 ItemData) | - | - | - | - |
| **U3 던전 · 요청** | O (아이템 상태 · 입고, 요청 아이템 예약) | O (보상 지급: 골드 · EXP) | - | - | S (던전 완료 시 저장 신호) |
| **U4 상점** | O (입력공간 입고, 출력공간 판매 대상) | O (골드 차감, 판매 대금 지급) | O (던전 완료 후 상점 진입 신호) | - | - |
| **U5 저장 · 플랫폼** | O (아이템 상태 스냅샷) | O (골드 · EXP · 증강 스냅샷) | O (던전 번호, 실패 수 스냅샷) | O (입력 · 출력공간 상태 스냅샷) | - |

## 의존 방향 점검

- **순환 의존 없음**: U1 → (없음) 이 기반. U2 는 U1 만, U3 는 U1 · U2, U4 는 U1 · U2 · U3, U5 는 전체를 읽기만 함
- **U5 는 쓰기 주체가 아님**: 저장과 복원 시 다른 unit 의 상태를 읽고 쓰지만, 게임 규칙은 소유하지 않음
- **U3 → U5 는 시그널**: 던전 완료 시 저장을 트리거하며, 직접 호출하지 않음 (AD-4 시그널 중심)

## 구현 순서에 따른 의존

| 순서 | 슬라이스 | 필요한 unit (완성 상태) |
| --- | --- | --- |
| 1 | 튜토리얼 | U1, U2 (최소) |
| 2 | 던전 1 | U1, U2, U3, U5 (자동 저장 최소) |
| 3 | 상점 | U1, U2, U3, U4 |
| 4 | 저장 · 플랫폼 | U1 ~ U5 전체 |

## 공유 자원

| 자원 | 소유 unit | 사용하는 unit | 변경 규칙 |
| --- | --- | --- | --- |
| `ItemData` (.tres) | U1 | U2, U3, U4 | 읽기 전용으로 사용, 값 변경은 U1 에서만 |
| `ItemInstance` 상태 | U1 | U3, U4, U5 | 상태 전환은 ItemManager 메서드로만 (FR-09) |
| 공유 골드 `GoldLedger` | U2 | U3, U4, U5 | 증감은 EconomyManager 메서드로만 (NFR-04) |
| `DungeonTable` (JSON) | U3 | U4, U5 | 읽기 전용 |
| 세이브 스냅샷 형식 | U5 | 모든 unit | 필드 추가 시 U5 에서 버전 갱신 |

## 리스크

| 리스크 | 영향 unit | 대응 |
| --- | --- | --- |
| 튜토리얼 슬라이스에서 골드 표시가 U2 완성 전에 필요 | U1, U2 | U2 최소 표시만 먼저 구현 (순서 1) |
| 저장 형식 변경이 여러 unit 에 영향 | U5 와 전체 | 스냅샷 버전 번호를 두고 unit 추가 시 갱신 |
| 상점 입력공간 용량 값 미정 | U4 | Code Generation 에서 기본값을 정하고 테스트로 조정 |
